GM01 · Gemini Robotics 家族里有哪三类模型？各自的输入输出是什么？哪个能公开调用？

来源：第 1 章 第一步 · 加入 2026-11-20 · 复习记录：

答案
模型 角色 输入 → 输出
Gemini Robotics-ER 大脑（VLM） 图像 / 视频 / 语音 / 文字 → 文字、指点、检测框、计划、工具调用

口诀：工长拆活熟练工干。

GM02 · GR 1.5 的 agentic 系统里，orchestrator 和 action model 分别由谁实现、做什么？两者之间传的是什么？

来源：第 1 章 第二步 · 加入 2026-11-20 · 复习记录：

答案
  • Orchestrator = GR-ER 1.5：处理用户输入和环境反馈，拆任务，做成功检测决定何时进下一步，可调用搜索等数字工具。
  • Action model = GR 1.5（VLA）：把指令翻译成底层动作；对 orchestrator 来说是一个工具。
  • 中间传的是一句开放词汇的自然语言子指令（如"把雨衣装进行李箱"）。好处：两边可以分开升级；代价：一句话说不清精确位置和力度。

1.5 报告 §2.1 L141–L152；ER 2 博客：开发者把 VLA、导航 API 声明成工具（L94）。

口诀：中间只传一句话。

延迟与动作块

GM04 · GR 1.0 的 VLA 怎么拆成两半？backbone 延迟、端到端延迟、有效控制频率各是多少？

来源：第 1 章 第三步 · 加入 2026-11-20 · 复习记录：

答案
  • 云端 backbone：Gemini Robotics-ER 的蒸馏版，问答延迟从几秒优化到 < 160 ms。
  • 本地 action decoder：跑在机器人上，补偿 backbone 的延迟。
  • 端到端（观测 → 一块动作）约 250 ms；一块有多个动作，有效控制频率 50 Hz。

1.0 报告 §3.1 L830–L837。

口诀：大脑慢就一块多给。

GM05 · 延迟 L、控制频率 f，一个动作块至少要多少步才不卡？块不够长时有效频率是多少？用 250 ms、50 Hz 算一遍。

来源：第 1 章 第三步 · 加入 2026-11-20 · 复习记录：

答案

\(K_{\min} = \lceil L \times f \rceil\)；块长 \(K\) 不够时，稳态有效频率 \(f_{\text{eff}} = \min(K / L,\ f)\)。

250 ms × 50 Hz = 12.5 → 至少 13 步。只给 10 步：一块覆盖 200 ms，每个 250 ms 周期卡 50 ms，有效频率 \(10 / 0.25 = 40\) Hz。

（论文没公开 chunk 长度，13 是按 250 ms 和 50 Hz 反推的下限。）

口诀：延迟乘频率是下限。

读官方数字

GM06 · 看机器人模型官方博客里的成功率数字，要先问哪三个问题？82% → 99.5% 的越狱抵抗率换成失败率是降到几分之一？

来源：第 1 章 第五步 · 加入 2026-11-20 · 复习记录：

答案

三问：跟谁比（多半是自家上一代）、绝对还是相对（0% → 93% 不可能是相对提升）、测了多少次（看误差条和试验次数）。

失败率：\((1-0.82)/(1-0.995) = 0.18/0.005 = 36\)，降到 1/36。接近 100% 的成功率，换成失败率比更能看出差距。

例：用夹子装糕点 5% → 100%：绝对 +95 pp，相对 ×20。

口诀：跟谁比、绝对相对、测几次，近百就换失败率。
